## Title

CounterLab — A scientific debugger for beliefs

## Tagline

Ask like chat. Prove it like science.

## Short description

CounterLab turns a learner's supported notebook claim into two competing
models, an immutable Prediction, the smallest verified discriminating Test, a
signed or integrity-hashed Boundary Map, deterministic transfer, and a minimal
repair unlocked only after transfer passes.

## Product story

A fluent explanation can leave the original misconception untouched.
CounterLab instead asks the learner to state the Question and commit a
Prediction before any result appears. It then changes one deployment-relevant
condition, keeps the controls visible, and lets fixed computation and a frozen
verifier decide what the evidence supports.

The fastest lesson starts with a familiar failure: a churn notebook reports
excellent accuracy when rows are split randomly, even though the same customer
can appear in training and test. CounterLab compares that evidence with a
whole-customer holdout and identity ablation. The learner explores the verified
Boundary, applies the rule to a time-ordered forecasting case, and only then
unlocks a correction to a copy of the notebook.

The learner journey is one stable sequence:

1. **Question** — frame the uncertainty and bind it to exact notebook cells.
2. **Prediction** — confirm the Belief Spec and seal an expectation and confidence.
3. **Test** — inspect Why this test? while a fixed scorer selects a registered intervention.
4. **Boundary** — explore verified cells showing where the conclusion changes.
5. **Apply** — use the rule on a surface-different case scored by fixed code.
6. **Repair** — download a minimal verified notebook copy and Proof Capsule.

The Evidence Verdict is exactly `SUPPORTS`, `INCONCLUSIVE`, or `REJECTED`.
CounterLab never labels the learner wrong and releases no result from a rejected
test.

## What is technically distinct

CounterLab separates authority instead of asking one model to propose, compute,
and approve its own answer:

- **GPT-5.6 reasoning analyst** proposes an evidence-linked Belief Spec from the
  learner-approved sanitized packet. It cannot run cells or produce result
  authority.
- **Runtime Codex compiler** emits a bounded Discrimination Contract,
  CounterLab Experiment IR, scene description, rationale, or separate Patch
  Plan. It can compose registered operation IDs but cannot author hosted code,
  formulas, metrics, or verified result values.
- **Fixed Subject Pack scorer and kernels** select the experiment and compute
  every authoritative split, metric, Boundary cell, transfer result, and patch
  recomputation.
- **Frozen verifier** owns technical and epistemic validity, result-to-UI
  binding, mutation detection, reproducibility, and patch scope.
- **Learner** owns the Question, model confirmation, immutable Prediction,
  revision, transfer action, and repair approval.

The final Reasoning Diff is learner-facing. Proof Capsule v2 is machine-facing
and binds the mode, evidence, prediction, selected experiment, canonical IR,
compiler events, verifier reports, result, Boundary Map, transfer, repair,
event chain, versions, limitations, and reproduction commands.

## Honest product boundary

The release contains exactly two reviewed ML Subject Packs: entity leakage and
class imbalance/metric choice. It does not claim arbitrary notebook support,
all STEM, global mastery, causal truth beyond the test, or prose grading.
Physics/free-fall is not part of this release.

Notebook intake supports documented `nbformat` 4 Python/scikit-learn patterns,
never executes uploaded cells, and sends only the learner-approved sanitized
packet to the reasoning analyst. Raw rows, the notebook file, secrets, and
local paths are excluded.

Hosted Runtime Codex uses a credential-and-privilege launch boundary with a
fixed non-root UID, `setpriv --no-new-privs`, and source-free typed plans. It
has no mount namespace or filesystem read allowlist,
so filesystem generation read isolation is explicitly `PARTIAL`. Fixed scoring,
execution, and verification remain independent of generated output.

## Evidence modes

- **Verified sample lesson** — bundled approved evidence, no account or model
  credential, and no claim that the run is live.
- **Live notebook analysis** — artifact-specific analyst and runner work backed
  by the deployed Worker and Container; it never falls back to sample or replay.
- **Verified replay** — read-only reconstruction of stored evidence with no new
  model call or experiment.
