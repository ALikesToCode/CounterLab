# Devpost copy

## Title

CounterLab — CI for Understanding

## Tagline

Treat a learner's claim like code: test it against reality before merging the
repair.

## Short description

CounterLab turns a supported ML notebook into an evidence-linked Belief Test,
immutable prediction, externally verified counterexperiment, fixed transfer
task, and transfer-gated copied-notebook repair.

## Longer description

A chatbot can explain leakage while a learner continues trusting the wrong
evidence. CounterLab makes the learner commit first, then lets a fixed kernel and
external verifier answer. Its customer-churn notebook looks excellent under a
random row split because customer identity crosses train and test. A whole-
customer split and identity ablation reveal the gap.

GPT-5.6 formalizes the claim into two evidence-linked hypotheses. Runtime Codex
compiles a source-free Experiment Plan containing only registered operations;
it cannot compute metrics or approve itself. A fixed Python interpreter and
independent verifier decide whether a result may render. After the learner
revises a reusable rule, a surface-different deterministic transfer—not an LLM
grade—unlocks a source-free Patch Plan and verified repair to a notebook copy.
The final Reasoning Diff and Proof Bundle connect belief, prediction, computed
evidence, transfer, code, and provenance.

CounterLab includes two end-to-end concept packs: repeated-entity leakage and
class imbalance/metric choice. The second uses a rare-event notebook, majority
baseline, confusion matrix, precision/recall/F1/PR-AUC, threshold and prevalence
controls, a manufacturing transfer, and an independently verified evaluation
patch.

The checked-in replay is genuine: an authenticated Codex run was rejected after
two repairs, and a separate later run passed 18 invariants and all 12 published
mutations. CounterLab labels both honestly and documents that generation-time
host read isolation remains partial.

## Judge instructions

1. Open the deployed Studio after the production smoke identifier in the release notes, or run `./scripts/clean-demo.sh` locally.
2. Choose Analyze a notebook for the artifact-specific hosted path, or Try the 3-minute sample for the no-secret path.
3. Choose Verified replay to inspect the persistent label and genuine
   reject/repair plus later verified trace.
4. Use `./scripts/reproduce-session.sh leakage-01` to reproduce the candidate,
   canonical result, mutation matrix, and patch under Docker.
5. Inspect `docs/ACHIEVED_METRICS.json` and `docs/HELD_OUT_RESULTS.json`; they
   contain executed software metrics, explicit failures, and no invented
   learner outcomes.
