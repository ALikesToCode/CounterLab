2. **Judge Mode has a strong desktop editorial hook.** Its false 98.5% versus reliable 59.4% contrast and belief-breaking thesis are memorable, even though the proof remains static and drops below the first mobile fold.
3. **Trust mechanisms go beyond demo theater.** Immutable Prediction, tri-state `SUPPORTS | INCONCLUSIVE | REJECTED`, binding hashes, mutation tests, copied patch verification, event chains, and Proof Capsule v2 form a coherent evidence system.
4. **The backend is unusually production-minded for a hackathon.** D1/R2 separation, signed one-job tokens, optimistic state transitions, idempotent callbacks, cursor reconnect, cancellation, private artifacts, and exact-byte proof/patch checks are implemented and tested.
5. **The public shell is available, responsive, and honest about important limits.** Worker 82 health is green; observed routes rendered without unexpected console/network errors; required viewports had no horizontal overflow; cold/throttled LCP was strong; the repository records `NO_DATA` instead of inventing learner outcomes.

1. **The project is not submitted.** This alone keeps the official score at zero.
2. **The exact public release is not qualified.** Worker 82 is healthy but not bound to the audited commit/Container or a complete live/sample/replay/export/browser matrix.

4. **GPT-5.6 is underused and the fast learner paths remain fragile.** It performs one structured Belief Spec call rather than a bounded continuing inquiry/presentation loop; claim-only routing, replay practice authority, and the sample Boundary also weaken the core promise.
